# WGMM 算法普适性分析

## 状态

已完成，并已按当前 `wgmm_monitor/` 模块化实现同步。

## 目标

评估当前 WGMM 调频算法对不同 UP 主发布模式的适用边界。这里的“普适性”只指时间序列周期性监控场景，不代表算法能预测事件驱动或完全随机的发布行为。

## 当前实现依据

相关代码：

- `wgmm_monitor/wgmm/features.py`
- `wgmm_monitor/wgmm/learning.py`
- `wgmm_monitor/wgmm/scoring.py`
- `wgmm_monitor/wgmm/scheduler.py`
- `wgmm_monitor/services/frequency.py`

核心机制：

- 固定时间维度：日、周、月内周、年内月。
- 附加时间维度：自相关发现的 `custom_N` 非日历周期。
- 正向样本：`data/mtime.txt`。
- 负向样本：`data/miss_history.txt`。
- 学习门槛：10 条离开学习期，20 条学习权重/sigma，50 条尝试发现附加周期。
- 决策输出：`data/wgmm_config.json` 中的 `next_check_time`。

## 核心假设

WGMM 假设发布行为至少有一部分可以由周期性时间特征解释：

```text
历史发布时间
    -> 周期特征
    -> 加权高斯相似度
    -> 正向得分 - 负向惩罚
    -> 未来峰值扫描
    -> 下一次检查时间
```

算法对“有规律但不完全固定”的行为最有效；对外部事件驱动的行为只能退化为较保守的轮询。

## 发布模式分类

| 类型 | 特征 | 预期效果 |
|------|------|----------|
| 高频规律型 | 每天或几乎每天固定时段发布 | 优秀 |
| 周期规律型 | 每周固定几天或固定时段发布 | 优秀 |
| 多峰型 | 一天或一周内多个高峰 | 良好 |
| 固定 N 天型 | 每 N 天发布，N 不一定是 7 的倍数 | 当前实现较旧版更好 |
| 月度规律型 | 每月固定周或固定窗口发布 | 中等 |
| 季节性型 | 频率随月份或假期变化 | 中等 |
| 渐变型 | 发布习惯逐步改变 | 良好 |
| 低频不规律型 | 数据少且无明显模式 | 一般 |
| 突发事件型 | 外部事件触发，长期沉寂后爆发 | 较弱 |

## 逐类分析

### 高频规律型

日内时间集中，正向历史积累快。

预期学习结果：

- `day` 权重提高。
- `day` sigma 降低。
- lambda 较低，保留长期稳定模式。

这是最适合 WGMM 的场景。

### 周期规律型

周内时间和日内时间都有集中趋势。

当前 `week` 特征使用一周内秒数编码，能够同时表达星期和当天时间，因此对“周三晚上”这类模式较友好。

预期效果优秀。

### 多峰型

例如上午和晚上都可能发布。

WGMM 的得分类似核密度估计，每个历史事件都会贡献一个高斯核，因此天然支持多个峰。潜在问题是 sigma 学习按整个维度的离散度估计，多峰之间可能被较宽的 sigma 平滑，但整体仍能给出可用结果。

### 固定 N 天型

旧的四维固定周期很难表达“每 3 天”或“每 10 天”。当前实现增加了 `discover_periods()`，在正向历史达到 50 条且跨度足够时，可以发现部分非日历周期并加入 `custom_N` 特征。

限制：

- 数据不足时不会发现。
- 自相关会过滤日/周/月/年附近周期和谐波。
- 发现周期后仍需要后续样本学习权重和 sigma。

结论：比固定四维模型更通用，但不是保证命中所有 N 天周期。

### 月度规律型

月更或半月更数据积累慢。

问题：

- 10 条正向样本可能需要很多个月。
- 20 条样本后才学习权重和 sigma。
- `month_week` 是粗粒度桶，无法精确表达每月某一天。

可用，但收敛慢。

### 季节性型

`year_month` 可以表达月份偏好，但季节性通常需要跨年数据。lambda 在高方差期间可能加快遗忘，这与保留上一年同季数据存在天然张力。

实际监控中，这类模式通常表现为活跃期样本变密、间隔缩短，淡季样本稀疏、间隔变长。算法行为通常可接受。

### 渐变型

指数衰减和自适应 lambda 是为此类场景准备的。

当间隔方差上升时，lambda 上升，旧模式更快淡出；当新模式稳定后，lambda 回落。过渡期可能暂时不准，但会随新数据调整。

### 低频不规律型

没有稳定周期时，所有维度得分趋于接近，未来扫描也难以找到明确峰值。

这是合理退化：算法不应虚构规律。此时检查间隔主要受历史间隔和扫描窗口影响，请求节省率低于规律型 UP 主。

### 突发事件型

外部事件驱动的爆发通常不由日、周、月、年或固定 N 天周期决定。WGMM 无法提前知道外部事件，因此预测能力弱。

算法仍会：

- 在爆发期间因新正向样本调整频率。
- 在沉寂期间通过负向样本和低得分降低检查压力。

但它不是事件预测系统。

## 综合评估

| 发布模式 | 数据需求 | 预测质量 | 请求节省 |
|----------|----------|----------|----------|
| 高频规律型 | 低 | 高 | 高 |
| 周期规律型 | 低到中 | 高 | 高 |
| 多峰型 | 中 | 中高 | 中高 |
| 固定 N 天型 | 中到高 | 中到高 | 中 |
| 月度规律型 | 高 | 中 | 中 |
| 季节性型 | 高 | 中 | 中 |
| 渐变型 | 中 | 中高 | 中高 |
| 低频不规律型 | 高 | 低 | 低到中 |
| 突发事件型 | 不稳定 | 低 | 低 |

## 适用边界

WGMM 适合：

- 有日内、周内、月内、季节性或固定间隔规律的 UP 主。
- 发布习惯缓慢变化的 UP 主。
- 需要稳定无人值守监控、可接受少量检测延迟的场景。

WGMM 不适合：

- 完全由热点或外部事件驱动的发布。
- 数据极少且长期无历史积累的目标。
- 要求毫秒级或强实时检测的场景。
- 需要解释内容语义、标题、互动指标的推荐系统场景。

## 结论

当前 WGMM 具有“有条件的普适性”：

- 对多数周期性或半周期性发布模式有效。
- 对固定 N 天模式已有 `custom_N` 改进，但需要足够数据。
- 对低频随机和突发事件型发布只能安全退化，不能提供强预测。

这与项目定位一致：WGMM 是监控调频工具，目标是减少无效请求并保持可接受的发现延迟，而不是成为通用预测系统。
